# 解答・解説: 2つのスタックでキューを実装する

## 解法の方針

追加用スタック `incoming` と、取り出し用スタック `outgoing` を用意します。

- 操作 `1 x` では `x` を `incoming` に積みます。
- 操作 `2` と `3` では、`outgoing` が空のときに限り、`incoming` の全要素を1つずつ `outgoing` へ移します。
- `outgoing` の先頭（スタックの頂上）がキューの先頭です。操作 `2` では取り出し、操作 `3` では値を見るだけにします。
- 両方のスタックが空なら `EMPTY` を出力します。

要素を移し替えるたびに順序が反転するため、`outgoing` から取り出す順序はキューのFIFO順になります。`outgoing` に要素が残っている間は移し替えないことが重要です。

## 正当性

`incoming` には新しく追加された要素が追加順に積まれます。`outgoing` が空になるとき、`incoming` をすべて移すことで追加順が反転し、最も古い要素が `outgoing` の頂上になります。そのため、取り出し操作は常に最も先に追加された要素を返します。

`outgoing` に要素が残っている間は、そこにある要素が `incoming` の全要素より先に追加されています。移し替えを保留することで、キュー内の順序が保たれます。以上から、すべての取り出し・先頭確認操作はFIFO順に従います。

## 計算量

- 追加: `O(1)`
- 取り出し・先頭確認: 償却 `O(1)`。個々の操作では最大 `O(Q)` かかる場合がありますが、各要素は `incoming` から `outgoing` へ高々1回だけ移されます。
- 空間計算量: `O(Q)`

## Java 解答例

学習者が回答を書くファイルは `src/main/java/Main.java` です。完成した模範解答は `src/main/java/reference/ReferenceMain.java` に分けています。

## 実装上の注意

- `outgoing` が空のときだけ要素を移します。毎回移すとキュー順を壊します。
- 操作 `3` は確認だけなので、頂上の要素を取り出さないようにします。
- 整数値として `-1` も入力できるため、空キューを `-1` で表さず、出力上は `EMPTY` と区別します。
